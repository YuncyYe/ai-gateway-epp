# 详细设计-01：包结构与进程配置

## 1. 包结构

```
ai-gateway-epp/
├── cmd/epp/
│   └── main.go                  # 组合根：配置解析 → 组件装配 → 启动
├── pkg/
│   ├── cell/
│   │   ├── manager.go           # CellManager：Cell 注册表 + 生命周期编排
│   │   ├── cell.go              # Cell：数据面 + 政策面 + 角色
│   │   ├── engine.go            # Engine 编译（含 drain 调度）
│   │   └── role.go              # Role 类型与转换矩阵
│   ├── demux/
│   │   ├── demux.go             # pool metadata → Cell 路由
│   │   └── server.go            # ext-proc server 封装（多 Cell 版 StreamingServer）
│   ├── poller/
│   │   ├── poller.go            # 通用轮询器：version 增量/退避/指标
│   │   ├── discovery.go         # ClusterDiscovery
│   │   ├── config.go            # ConfigPoller
│   │   └── assignment.go        # AssignmentWatcher
│   ├── innerapi/
│   │   ├── client.go            # HTTP client：鉴权/信封解析/重试
│   │   └── types.go             # VersionedResponse 等共享类型
│   ├── assignment/
│   │   └── types.go             # 角色视图类型（与 ai-gateway-api 契约）
│   └── eppplugin/
│       └── clustertable/        # cluster-table-discovery 插件（实现 llm-d EndpointDiscovery）
└── go.mod                       # require github.com/llm-d/llm-d-router vX.Y.Z
```

**依赖方向**：`cmd → {cell, demux, poller, eppplugin}`；`poller → innerapi, cell, assignment`；`demux → cell`；`cell → llm-d 引擎包`。禁止反向依赖。

各包职责一句话：

| 包 | 职责 | 不做什么 |
|---|---|---|
| cmd/epp | 装配与启动 | 不含调度/流控装配逻辑（那是 Cell 内的事） |
| cell | Cell 生命周期与引擎热切换 | 不直接做 IO（IO 在 poller） |
| demux | 请求路由 | 不持有引擎状态 |
| poller | 全部对外拉取 | 不决定策略，只搬运变更到 Manager API |
| innerapi | HTTP 契约 | 不感知业务 |
| eppplugin | llm-d 插件接口适配 | 不含拉取逻辑（取数由 poller/discovery 提供，见 03 §4） |

## 2. 进程级配置（启动参数）

```go
type Config struct {
    // 身份与接入
    InstanceID   string        // 实例标识，assignment 上报用；默认 hostname
    APIAddr      string        // ai-gateway-api inner-api 地址（http://host:port）
    APIToken     string        // 鉴权 Token（env AI_GATEWAY_API_TOKEN 优先）
    PollInterval time.Duration // 三个 poller 默认 5s
    PollTimeout  time.Duration // 单次请求超时，默认 3s

    // 服务端口
    GRPCPort    int  // ext-proc 业务端口，默认 9002
    HealthPort  int  // gRPC health 端口，默认随 GRPCPort
    MetricsPort int  // /metrics + pprof，默认 9090
    EnablePprof bool // 默认 false（生产收敛，FR-O6）

    // 行为开关
    DefaultPool        string        // demux 缺 pool metadata 时的兜底 cluster，空=拒绝
    EngineDrainTimeout time.Duration // 旧引擎/Cell drain 强杀上限，默认 60s
}
```

**启动顺序**：`Config 解析 → innerapi.Client → CellManager(empty) → 三 Poller 注册 → demux server 装配（持 CellManager 引用）→ health/metrics server → 等 AssignmentWatcher 首拉成功 + 各自 Cell Ready → 对外服务`。

## 3. 部署形态

- 每实例一个进程级 Config（§2），cluster 级配置全部来自 picker_config
- 实例组拓扑不进进程配置：实例只知道自己是谁（InstanceID），角色全听 assignment——**实例可互换**，组内任意实例可被分配器互换角色（NFR-5 零接触的前提）
- 插件注册列表在 cmd 组合根重建（参照 `llm-d-router/cmd/epp/runner.go:725-729`），只注册无 K8s 依赖的内置插件 + 自研 `cluster-table-discovery`
