# TC-01 调度闭环

| 项 | 内容 |
|---|---|
| 用例编号 / 名称 | TC-01 / 调度闭环 |
| 所属场景 | SC01 单 cluster 调度闭环 |
| 版本 | v0.1 |

## 测试目的

验证 ai-gateway-epp 端到端最小链路成立：配置下发 → 后端发现 → ext-proc 调度返回目标端点 → 真实请求到达 inference-sim 并收到正常响应。

## 运行模式

单组件进程组：epp（真实进程）×1 + inference-sim（真实进程）×2 + ai-gateway-api mock + BFE 由测试代码扮演。

## 前置条件

1. harness 已构建 epp 二进制；inference-sim 二进制可用。
2. mock API 已配置 assignment 全量视图（cluster-a → 本实例 primary）、epp_config（cluster-a 最小配置）、cluster_table（2 个 sim 后端，Weight=50/50）。
3. epp 启动并就绪（health=SERVING，代表 assignment 首拉成功且 cell ready）。

## 测试步骤

| # | 操作 | 预期 |
|---|---|---|
| 1 | 建立 ext-proc gRPC stream，发送 RequestHeaders，dynamic metadata 带 `llm-d.ai/inference-pool = "cluster-a"`，path `/v1/chat/completions`，随后发送 RequestBody（OpenAI chat 请求，`"max_tokens": 8`） | epp 不报错 |
| 2 | 读取调度响应（RequestHeaders/Body 响应中的 dynamic metadata） | `x-gateway-destination-endpoint` 存在，值为 `ip:port` 且属于两个 sim 后端之一；响应带 `ClearRouteCache` |
| 3 | 向该 endpoint 发真实 OpenAI 请求 | sim 返回 200，body 为合法 chat.completion（内容可为 echo/random） |
| 4 | 重复步骤 1-3 共 20 次 | 每次选中端点均有效；进程无 panic（metrics `ai_epp_demux_errors_total` 为 0） |

## 预期结果

- 全部步骤通过；epp 的 stderr 日志无 error 级记录（fail 时 harness 自动 dump）。
- `ai_epp_engine_current_version{cluster="cluster-a"}` 存在且非空。

## 清理

`defer e.Close()`：Kill epp/sim 进程并 Wait，关闭 mock API 与 gRPC 连接，`t.TempDir` 自动清理。
