# 场景说明：SC01 单 cluster 调度闭环

所属场景编号：SC01；代码目录：`test/implementation/scenario-SC01-single-cluster-scheduling`（包名 `sc01`）。

## 1. 背景与目的

验证 ai-gateway-epp 最小完整链路：从 ai-gateway-api（mock）拉取 assignment / picker_config / cluster_table，发现 inference-sim 后端，对带 `llm-d.ai/inference-pool` metadata 的 ext-proc 请求完成调度并返回目标端点。本场景是其余所有场景的前置基础。

## 2. 运行模式

单组件进程组（每 TC 独立一套）：

| 进程/组件 | 形态 | 说明 |
|---|---|---|
| ai-gateway-epp | 真实进程 | harness 构建的二进制；grpc(动态)/health(动态)/metrics(动态) 端口 |
| inference-sim ×2 | 真实进程 | 假模型名（模拟分词器，零外部依赖）；OpenAI HTTP + /metrics |
| ai-gateway-api | mock（测试进程内） | assignment/picker_config/cluster_table/report，version 增量 |
| BFE | 测试代码扮演 | ext-proc gRPC 客户端 |

## 3. 配置构造

- **mock API 数据**
  - assignment：`{"cluster-a": "primary"}`（instance 参数匹配 epp 的 `-instance-id`）
  - picker_config：`cluster-a` → 最小可用配置（queue-scorer + kv-cache-utilization-scorer + max-score-picker + cluster-table-discovery + openai-parser；flowControl 可关）
  - cluster_table：`cluster-a.sub-1 = [sim0(Weight=50), sim1(Weight=50)]`，Addr/Port 为 sim 实例动态地址
- **epp 启动参数**：`-api-addr <mock>` `-instance-id epp-sc01` `-poll-interval 200ms` `-grpc-port <p>` `-health-port <p>` `-metrics-port <p>`，日志写入 `t.TempDir()`

## 5. 依赖与就绪

1. 启动顺序：mock API → sim ×2（WaitForTCP）→ epp（WaitForTCP grpc 端口）→ 轮询 health 至 SERVING。
2. sim 的 /metrics 可被 epp 采集是 scorer 生效的前提；TC-01 以"响应 200 + 选中端点在 sim 集合内"为通过标准，不做加权精度断言。
