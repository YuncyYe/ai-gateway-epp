# TC-01 配置变更热生效

| 项 | 内容 |
|---|---|
| 用例编号 / 名称 | TC-01 / 配置变更热生效 |
| 所属场景 | SC02 配置热加载 |
| 版本 | v0.1 |

## 测试目的

验证 picker_config 内容变化后，ai-gateway-epp 无需重启即可完成引擎换入：`ai_epp_engine_current_version` 内容哈希前移，换入后调度行为保持正确。

## 运行模式

单组件进程组：epp（真实进程）×1 + inference-sim（真实进程）×1 + ai-gateway-api mock + BFE 由测试代码扮演。对应实现 `sc02_test.go` 的 `TestTC01_HotReload`（env 标识 `epp-sc02-tc01`）。

## 前置条件

1. harness 已构建 epp 二进制；inference-sim 二进制可用。
2. mock API 已配置 assignment（cluster-a=primary）、picker_config v1（cluster-a 最小配置：ep-discover / kv-scorer / queue-scorer / `max-score-picker`（name=`max-score`））、cluster_table（cluster-a.sub-1 = [sim0, Weight=50]）。
3. epp 启动并就绪，`ai_epp_engine_current_version{cluster="cluster-a",version="<v1哈希>"}` 存在且非空。
4. 轮询间隔 200ms，版本变化观察窗口 20s。

## 测试步骤

| # | 操作 | 预期 |
|---|---|---|
| 1 | 从 epp metrics 读取 `ai_epp_engine_current_version{cluster="cluster-a"}` 的版本值，记为 v1 | v1 非空（已有编译引擎） |
| 2 | mock 将 cluster-a 的 picker_config 替换为 v2（最小配置中插件 `max-score` 重命名为 `max-score-v2`，内容哈希变化、仍合法） | mock 下发成功 |
| 3 | 轮询 epp metrics（20s 窗口），等待 cluster-a 引擎版本变化 | `ai_epp_engine_current_version{cluster="cluster-a"}` 变为新值且非空 |
| 4 | 建立 ext-proc gRPC stream 发送 pick 请求（metadata `llm-d.ai/inference-pool = "cluster-a"`，path `/v1/chat/completions`，body `{"model":"sim-model",...,"max_tokens":8}`，超时 10s） | 调度成功，返回端点为 sim 后端 `ip:port`（`e.ClusterSims["cluster-a"][0]`） |

## 预期结果

- 步骤 3：版本哈希从 v1 前移，全程无 epp 进程重启。
- 步骤 4：热加载后旧链路不断、调度结果正确。
- 观测指标：`ai_epp_engine_current_version`（内容哈希前移）、`ai_epp_engine_reloads_total`（换入计数）。

## 清理

`defer e.Close()`：Kill epp/sim 进程并 Wait，关闭 mock API 与 gRPC 连接，`t.TempDir` 自动清理。
