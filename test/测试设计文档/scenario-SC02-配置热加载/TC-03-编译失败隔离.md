# TC-03 编译失败隔离

| 项 | 内容 |
|---|---|
| 用例编号 / 名称 | TC-03 / 编译失败隔离 |
| 所属场景 | SC02 配置热加载 |
| 版本 | v0.1 |

## 测试目的

验证非法 epp_config 的 fail-static 行为：下发含未注册插件类型的配置后，编译失败被隔离记录（`result="invalid"` 计数出现），旧引擎版本保持不变并继续正常服务。

## 运行模式

单组件进程组：epp（真实进程）×1 + inference-sim（真实进程）×1 + ai-gateway-api mock + BFE 由测试代码扮演。对应实现 `sc02_test.go` 的 `TestTC03_InvalidConfig`（env 标识 `epp-sc02-tc03`）。

## 前置条件

1. harness 已构建 epp 二进制；inference-sim 二进制可用。
2. mock API 已配置 assignment 全量视图（cluster-a → 本实例 primary）、epp_config v1（最小配置）、cluster_table（cluster-a.sub-1 = [sim0, Weight=50]）。
3. epp 启动并就绪，`ai_epp_engine_current_version{cluster="cluster-a"}` 存在且非空，记为 v1。
4. 非法配置构造：v1 中 `"type": "max-score-picker"` 替换为未注册的 `"no-such-plugin-type"`。
5. 轮询间隔 200ms，观察窗口 20s。

## 测试步骤

| # | 操作 | 预期 |
|---|---|---|
| 1 | 从 epp metrics 读取 cluster-a 引擎版本，记为 v1 | v1 非空 |
| 2 | mock 将 cluster-a 的 epp_config 替换为非法配置（插件类型 `no-such-plugin-type`） | mock 下发成功 |
| 3 | 轮询 epp metrics（20s 窗口），等待 reload 失败计数出现 | `ai_epp_engine_reloads_total{cluster="cluster-a",result="invalid"}` > 0 |
| 4 | 读取 cluster-a 当前引擎版本 | 仍等于 v1，非法配置未触发引擎换入 |
| 5 | 建立 ext-proc gRPC stream 发送 pick 请求（metadata `llm-d.ai/inference-pool = "cluster-a"`，path `/v1/chat/completions`，body `{"model":"sim-model",...,"max_tokens":8}`，超时 10s） | 旧引擎调度成功，返回端点为 sim 后端（`e.ClusterSims["cluster-a"][0]`） |

## 预期结果

- 非法配置编译失败被隔离：reload 以 `result="invalid"` 计数记录，引擎版本保持 v1。
- 旧引擎继续正常服务，请求不中断、进程不退出。

## 清理

`defer e.Close()`：Kill epp/sim 进程并 Wait，关闭 mock API 与 gRPC 连接，`t.TempDir` 自动清理。
