# TC-04 配置回滚

| 项 | 内容 |
|---|---|
| 用例编号 / 名称 | TC-04 / 配置回滚 |
| 所属场景 | SC02 配置热加载 |
| 版本 | v0.1 |

## 测试目的

验证配置回滚（FR-C5）：picker_config 改为新版本后又改回上一版本时，epp 依据内容哈希自动恢复旧引擎，全程无任何进程重启/重载类操作。

## 运行模式

单组件进程组：epp（真实进程）×1 + inference-sim（真实进程）×1 + ai-gateway-api mock + BFE 由测试代码扮演。对应实现 `sc02_test.go` 的 `TestTC04_Rollback`（env 标识 `epp-sc02-tc04`）。

## 前置条件

1. harness 已构建 epp 二进制；inference-sim 二进制可用。
2. mock API 已配置 assignment（cluster-a=primary）、picker_config v1（最小配置）、cluster_table（cluster-a.sub-1 = [sim0, Weight=50]）。
3. epp 启动并就绪，`ai_epp_engine_current_version{cluster="cluster-a"}` 存在且非空，记为 v1。
4. v2 配置：v1 中插件 `max-score` 重命名为 `max-score-v2`（哈希变化、仍合法）；回滚配置为 v1 原文（同内容 → 同哈希）。
5. 轮询间隔 200ms，版本变化观察窗口 20s。

## 测试步骤

| # | 操作 | 预期 |
|---|---|---|
| 1 | 从 epp metrics 读取 cluster-a 引擎版本，记为 v1 | v1 非空 |
| 2 | mock 将 cluster-a 的 picker_config 替换为 v2 | 下发成功 |
| 3 | 轮询 epp metrics（20s 窗口），等待 v2 引擎生效 | `ai_epp_engine_current_version{cluster="cluster-a"}` 变为非空且 ≠ v1 的新值 |
| 4 | mock 将配置改回 v1 原文 | 下发成功 |
| 5 | 轮询 epp metrics（20s 窗口），等待版本回落 | 引擎版本恢复为 v1（同内容哈希） |
| 6 | 建立 ext-proc gRPC stream 发送 pick 请求（metadata `llm-d.ai/inference-pool = "cluster-a"`，path `/v1/chat/completions`，body `{"model":"sim-model",...,"max_tokens":8}`，超时 10s） | 调度成功，返回端点为 sim 后端（`e.ClusterSims["cluster-a"][0]`） |

## 预期结果

- 配置改回 v1 后引擎版本哈希自动恢复 v1，调度正常。
- 回滚完全由配置内容驱动，无任何 epp 进程操作（FR-C5）。

## 清理

`defer e.Close()`：Kill epp/sim 进程并 Wait，关闭 mock API 与 gRPC 连接，`t.TempDir` 自动清理。
