# TC-05 生效时效

| 项 | 内容 |
|---|---|
| 用例编号 / 名称 | TC-05 / 生效时效 |
| 所属场景 | SC02 配置热加载 |
| 版本 | v0.1 |

## 测试目的

验证配置生效时效（NFR-2）：从配置提交到引擎换入的耗时在 2×pollInterval 量级内。实现取 2×200ms 为基准，另加 10 倍余量（上限 2s）以容忍 CI/Windows 上的进程调度抖动，同时仍能捕捉回退到分钟级的回归。

## 运行模式

单组件进程组：epp（真实进程）×1 + inference-sim（真实进程）×1 + ai-gateway-api mock + BFE 由测试代码扮演。对应实现 `sc02_test.go` 的 `TestTC05_EffectiveLatency`（env 标识 `epp-sc02-tc05`）。

## 前置条件

1. harness 已构建 epp 二进制；inference-sim 二进制可用。
2. mock API 已配置 assignment 全量视图（cluster-a → 本实例 primary）、epp_config v1（最小配置）、cluster_table（cluster-a.sub-1 = [sim0, Weight=50]）。
3. epp 启动并就绪，`ai_epp_engine_current_version{cluster="cluster-a"}` 存在且非空，记为 v1。
4. v2 配置：v1 中插件 `max-score` 重命名为 `max-score-v2`。
5. 轮询间隔 200ms（harness 默认）；时效上限 bound = 10 × 200ms = 2s；兜底观察窗口 20s。

## 测试步骤

| # | 操作 | 预期 |
|---|---|---|
| 1 | 从 epp metrics 读取 cluster-a 引擎版本，记为 v1 | v1 非空 |
| 2 | 记录当前时间 start；mock 将 cluster-a 的 epp_config 替换为 v2 | 下发成功 |
| 3 | 每 20ms 轮询 epp metrics，直到引擎版本变为非空且 ≠ v1 | 版本前移（20s 内未变化则 fail：配置未生效） |
| 4 | 计算耗时 `time.Since(start)` | 耗时 ≤ bound（2s = 2×pollInterval + 10x 调度抖动余量） |

## 预期结果

- 配置提交到引擎换入的耗时 ≤ 2s，满足 NFR-2（2×pollInterval 量级）。

## 清理

`defer e.Close()`：Kill epp/sim 进程并 Wait，关闭 mock API 与 gRPC 连接，`t.TempDir` 自动清理。
