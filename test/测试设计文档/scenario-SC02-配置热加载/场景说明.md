# 场景说明：SC02 配置热加载

所属场景编号：SC02；代码目录：`test/implementation/scenario-SC02-config-hot-reload`（包名 `sc02`）。

## 1. 背景与目的

验证 picker_config 的**无重启热加载**：ai-gateway-api 侧配置内容变化后，epp 经轮询发现新版本，为对应 cluster 重新编译调度引擎并原子换入；换入期间请求不中断。同时验证非法配置的 fail-static 行为（旧引擎继续服务）。

观测手段：`ai_epp_engine_current_version{cluster,version}` 内容哈希变化、`ai_epp_engine_reloads_total{cluster,result}` 计数。

## 2. 运行模式

同 SC01（单组件进程组，每 TC 独立一套；ai-gateway-api 为进程内 mock，BFE 由测试代码扮演）。

## 3. 配置构造

- assignment：`{"cluster-a": "primary"}`（TC-02 增加 `cluster-b`）
- picker_config v1：`common.PickerConfig()` 最小配置
- picker_config v2：v1 的插件重命名（`max-score` → `max-score-v2`），内容哈希变化、仍合法
- 非法配置：v1 中 `max-score-picker` 类型替换为未注册的 `no-such-plugin-type`
- cluster_table：`cluster-a.sub-1 = [sim0(Weight=50)]`

## 4. TC 列表

| 编号 | 名称 | 断言要点 |
|---|---|---|
| TC-01 | 热加载生效 | 记录 v1 哈希 → mock 下发 v2 → 轮询 metrics 至哈希变化 → 换入后调度仍正确 |
| TC-02 | 多 cluster 独立热加载 | 只改 cluster-b 配置：b 哈希变化、a 哈希不变 |
| TC-03 | 非法配置 fail-static | 下发非法配置 → `result="invalid"` 计数出现 → 哈希保持 v1 → 旧引擎调度正常 |
| TC-04 | 配置回滚 | 下发 v2 后改回 v1：版本标签恢复 v1 哈希、调度正常，无任何进程操作（FR-C5） |
| TC-05 | 生效时效 | 配置提交到引擎换入 ≤ 2×pollInterval（测试含 10x 调度抖动余量）（NFR-2） |

## 5. 依赖与就绪

同 SC01 §5。轮询间隔 200ms，版本变化观察窗口 20s。

## 6. 已知实现问题（本场景曾暴露）

- `engineCurrentVersion` 换入时用 `DeleteLabelValues(cluster)` 清理旧版本标签，但 client_golang 要求提供全部标签值，旧版本标签会残留。已修复为 `DeletePartialMatch(prometheus.Labels{"cluster": ...})`（`pkg/cell/manager.go`）。
