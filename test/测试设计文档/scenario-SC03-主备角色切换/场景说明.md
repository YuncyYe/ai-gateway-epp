# 场景说明：SC03 主备角色切换

所属场景编号：SC03；代码目录：`test/implementation/scenario-SC03-assignment-role-switch`（包名 `sc03`）。

## 1. 背景与目的

验证 assignment 全量视图驱动的主备角色生命周期：降备（primary→standby）后 ext-proc 拒绝服务（gRPC `Unavailable` + "cell is not serving"）；提升（standby→primary）后恢复服务（备 cell 热数据，开闸即服务）；摘除后 cell 被删除，其余 cluster 不受影响。

观测手段：ext-proc 错误语义 / 调度恢复；退役的 assignment report 路径仅以计数器断言**零上报**（`ReportCount()==0`）——failover 由 BFE 侧连接滞回驱动，EPP 无上报义务。

## 2. 运行模式

同 SC01（单组件进程组，每 TC 独立一套）。

## 3. 配置构造

- assignment 全量视图按 TC 演进：`{"cluster-a": {"primary": "<本实例>"}}` → `{"cluster-a": {"standby": "<本实例>"}}` → `{"cluster-a": {"primary": "<本实例>"}}`（或摘除；由 `SetAssignment` 以默认实例展开）
- epp_config / cluster_table：同 SC01 最小配置

## 4. TC 列表

| 编号 | 名称 | 断言要点 |
|---|---|---|
| TC-01 | 降备拒绝服务 | SetAssignment standby → 轮询至 pick 返回 `not serving` 错误；liveness 仍 SERVING；零上报 |
| TC-02 | 提升恢复服务 | standby 拒绝后再提升 primary → pick 恢复成功；零上报 |
| TC-03 | 摘除去 cell | 从 assignment 移除 cluster-a（保留 cluster-b）→ cluster-a pick 失败、cluster-b 正常；零上报 |

## 5. 依赖与就绪

同 SC01 §5。角色变化经 epp_data 轮询（200ms）生效，观察窗口 20s。
