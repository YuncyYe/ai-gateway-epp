# TC-01 扩容

| 项 | 内容 |
|---|---|
| 用例编号 / 名称 | TC-01 / 扩容 |
| 所属场景 | SC05 端点生命周期 |
| 版本 | v0.1 |

## 测试目的

验证 cluster_table 扩容：表中新增后端后，经轮询拉取 + discovery diff 异步生效，新端点不重启 epp 即成为调度目标，且两个后端都能被命中。

## 运行模式

单组件进程组：epp（真实进程）×1 + inference-sim（真实进程）×2 + ai-gateway-api mock + BFE 由测试代码扮演。本 TC 先以 1 个后端启动，运行期再拉起第 2 个 sim 并下发新表，全程不重启 epp。

## 前置条件

1. harness 已构建 epp 二进制；inference-sim 二进制可用。
2. mock API 已配置 assignment（cluster-a=primary）、picker_config（cluster-a 最小配置）；初始 cluster_table 仅含 1 个 sim 后端 a0（Name=`cluster-a-a0`，Addr=127.0.0.1，Port=sim-a0 端口，Weight=50）。
3. epp 启动并就绪（health=SERVING）。

## 测试步骤

| # | 操作 | 预期 |
|---|---|---|
| 1 | 启动新 sim 进程（进程名 `sim-a1`，model `sim-model`），经 `SetClusterTable` 下发新表：cluster-a/sub-1 含 a0、a1 两个后端，Weight 均为 50（Addr=127.0.0.1，Port 为各自 sim 动态端口） | mock 接受新表；discovery 经轮询（200ms）+ diff 异步发现新端点 |
| 2 | 轮询断言（`WaitFor`，超时 30s）：每轮发 5 次 pick（ext-proc gRPC，metadata `llm-d.ai/inference-pool = "cluster-a"`，path `/v1/chat/completions`，RequestBody 为 chat 请求体 `{"model":"sim-model","messages":[...],"max_tokens":8}`，单次超时 5s），记录被命中的 endpoint | 直至命中集合大小 = 2，即 a0、a1 两个后端地址都被选中过 |

## 预期结果

- 新端点 a1 在观察窗口（30s）内成为调度目标，两个后端均收到流量。
- epp 全程未重启，进程健康、无 panic。

## 清理

`defer e.Close()`：Kill epp/sim 进程并 Wait，关闭 mock API 与 gRPC 连接，`t.TempDir` 自动清理。
