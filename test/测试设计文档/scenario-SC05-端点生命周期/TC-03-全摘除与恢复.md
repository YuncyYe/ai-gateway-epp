# TC-03 全摘除与恢复

| 项 | 内容 |
|---|---|
| 用例编号 / 名称 | TC-03 / 全摘除与恢复 |
| 所属场景 | SC05 端点生命周期 |
| 版本 | v0.1 |

## 测试目的

验证全摘除边界：cluster_table 中全部后端 Weight=0 时调度失败但 epp 进程保持健康（liveness 仍 SERVING）；将 Weight 恢复为 50 后服务自动恢复，全程不重启进程。

## 运行模式

单组件进程组：epp（真实进程）×1 + inference-sim（真实进程）×1 + ai-gateway-api mock + BFE 由测试代码扮演。

## 前置条件

1. harness 已构建 epp 二进制；inference-sim 二进制可用。
2. mock API 已配置 assignment 全量视图（cluster-a → 本实例 primary）、epp_config（cluster-a 最小配置）、cluster_table 含 1 个后端 a0（Weight=50）。
3. epp 启动并就绪（health=SERVING）。

## 测试步骤

| # | 操作 | 预期 |
|---|---|---|
| 1 | 经 `SetClusterTable` 下发 a0 Weight=0 | mock 接受新表；discovery 异步摘除唯一后端 |
| 2 | 轮询断言（`WaitFor`，超时 30s）：对 `llm-d.ai/inference-pool = "cluster-a"` 发 pick（path `/v1/chat/completions`，chat 请求体，`max_tokens:8`，单次超时 3s） | pick 返回错误（无可用端点，调度失败） |
| 3 | 查询 epp liveness 健康状态（`WaitHealth`，超时 5s） | liveness = SERVING，进程健康存活 |
| 4 | 经 `SetClusterTable` 恢复 a0 Weight=50 | mock 接受新表 |
| 5 | 轮询断言（`WaitFor`，超时 20s）：再次对 cluster-a 发 pick | pick 成功且返回的 endpoint 恰为 a0 的 sim 地址，服务自动恢复 |

## 预期结果

- 全摘除期间调度失败且进程不退出、liveness 保持 SERVING。
- 恢复 Weight 后（异步传播，观察窗口 20s）服务自动恢复，命中端点为 a0。
- epp 全程无 panic。

## 清理

`defer e.Close()`：Kill epp/sim 进程并 Wait，关闭 mock API 与 gRPC 连接，`t.TempDir` 自动清理。
