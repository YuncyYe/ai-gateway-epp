# 场景说明：SC05 端点生命周期

所属场景编号：SC05；代码目录：`test/implementation/scenario-SC05-endpoint-lifecycle`（包名 `sc05`）。

## 1. 背景与目的

验证 cluster_table 驱动的端点生命周期管理，全程不重启 epp：

- **扩容**：表中新增后端 → 被 discovery 发现 → 成为调度目标；
- **摘除**：`Weight=0` → 从调度集合移除（Weight=0 语义 = 摘除，见 `pkg/poller/discovery.go`）；
- **全摘除**：无可用端点时调度失败、进程健康，恢复 Weight 后服务自动恢复。

## 2. 运行模式

同 SC01（单组件进程组，每 TC 独立一套）。SC05 的表更新经轮询（200ms）+ discovery 插件 diff 异步生效，断言一律用轮询而非即时断言。

## 3. 配置构造

- cluster_table 按 TC 演进，后端 Addr/Port 为 sim 动态地址，Weight 按用例设置
- assignment / picker_config：同 SC01 最小配置

## 4. TC 列表

| 编号 | 名称 | 断言要点 |
|---|---|---|
| TC-01 | 扩容 | 表从 [a0] 变为 [a0,a1] → 轮询 picks 直至两个后端都被命中 |
| TC-02 | Weight=0 摘除 | a1 置 0 → 轮询直至连续 picks 全部命中 a0、不再命中 a1 |
| TC-03 | 全摘除与恢复 | a0 置 0 → pick 失败、liveness SERVING → 恢复 50 → 轮询至服务恢复 |
| TC-04 | Weight 非比例 | 90/10 权重下两后端都被命中：Weight 仅注册/摘除开关，流量比例由调度策略决定（需求分析 §3.1.1） |

## 5. 依赖与就绪

同 SC01 §5。discovery 传播为异步，观察窗口 20–30s。
