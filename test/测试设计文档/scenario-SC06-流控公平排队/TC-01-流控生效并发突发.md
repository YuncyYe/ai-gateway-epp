# TC-01 流控生效并发突发

| 项 | 内容 |
|---|---|
| 用例编号 / 名称 | TC-01 / 流控生效并发突发 |
| 所属场景 | SC06 流控公平排队 |
| 版本 | v0.1 |

## 测试目的

验证 flowControl 特性门开启后流控配置能编译生效，且单 band 限流（priority=1，maxRequests=1）下 8 并发 pick 请求经排队后全部完成、路由正确——确认排队路径无死锁。

## 运行模式

单组件进程组：epp（真实进程）×1 + inference-sim（真实进程）×1（cluster-a/a0）+ ai-gateway-api mock + BFE 由测试代码扮演（详见总体说明 §1）。

## 前置条件

1. harness 已构建 epp 二进制；inference-sim 二进制可用（总体说明 §2）。
2. mock API 已配置 assignment 全量视图（cluster-a → 本实例 primary）、默认 epp_config、cluster_table（1 个 sim 后端 a0），epp 启动并就绪，旧引擎已编译（`ai_epp_engine_current_version{cluster="cluster-a"}` 非空）。

## 测试步骤

| # | 操作 | 预期 |
|---|---|---|
| 1 | 读取 cluster-a 当前引擎版本 v1；通过 mock API 下发流控配置：featureGates 含 `flowControl`，plugins 含 `utilization-detector`（name=util-detector），flowControl 段 `defaultRequestTTL: "30s"`、`saturationDetector.pluginRef: "util-detector"`、`priorityBands: [{priority: 1, maxRequests: 1}]`；等待（上限 20s） | `ai_epp_engine_current_version{cluster="cluster-a"}` 变为新版本（≠ v1），流控配置编译成功 |
| 2 | 同时发起 8 路并发 ext-proc gRPC pick（`llm-d.ai/inference-pool = "cluster-a"`，path `/v1/chat/completions`，OpenAI chat 请求 `"max_tokens": 8`，每路超时 30s） | 8 路请求全部成功返回，无超时、无错误（maxRequests=1 下其余请求经排队完成，不死锁） |
| 3 | 检查每路返回的 endpoint | 8 路全部路由到 `a0`（cluster-a 唯一后端），无错路由 |

## 预期结果

- 全部步骤通过；epp 的 stderr 日志无 error 级记录（fail 时 harness 自动 dump）。
- 流控引擎换入后并发突发全部完成，验证排队路径无死锁。

## 清理

`defer e.Close()`：Kill epp/sim 进程并 Wait，关闭 mock API 与 gRPC 连接，`t.TempDir` 自动清理。
