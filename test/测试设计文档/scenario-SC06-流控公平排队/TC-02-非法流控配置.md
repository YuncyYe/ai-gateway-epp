# TC-02 非法流控配置

| 项 | 内容 |
|---|---|
| 用例编号 / 名称 | TC-02 / 非法流控配置 |
| 所属场景 | SC06 流控公平排队 |
| 版本 | v0.1 |

## 测试目的

验证非法流控配置的 fail-static 行为：flowControl 段的 `saturationDetector` 引用不存在的插件时，配置编译失败被隔离（`result="invalid"` 计数出现），旧引擎保持服务不受影响。

## 运行模式

单组件进程组：epp（真实进程）×1 + inference-sim（真实进程）×1（cluster-a/a0）+ ai-gateway-api mock + BFE 由测试代码扮演（详见总体说明 §1）。

## 前置条件

1. harness 已构建 epp 二进制；inference-sim 二进制可用（总体说明 §2）。
2. 已按 TC-01 的方式将 cluster-a 切换到流控配置（featureGates 含 `flowControl`，util-detector + priorityBands=[{priority:1, maxRequests:1}]），流控引擎已编译，记录当前版本 v1。

## 测试步骤

| # | 操作 | 预期 |
|---|---|---|
| 1 | 通过 mock API 下发非法流控配置：`flowControl` 段 `defaultRequestTTL: "30s"`、`saturationDetector.pluginRef: "missing-detector"`（引用的插件不存在）、`priorityBands: [{priority: 1, maxRequests: 1}]` | — |
| 2 | 等待（上限 20s）并检查 reload 指标 | `ai_epp_engine_reloads_total{cluster="cluster-a",result="invalid"}` > 0，非法重载被记录 |
| 3 | 读取 `ai_epp_engine_current_version{cluster="cluster-a"}` | 版本仍为 v1，未因非法配置换入新引擎（fail-static） |
| 4 | 发起 ext-proc gRPC pick（`llm-d.ai/inference-pool = "cluster-a"`，path `/v1/chat/completions`，OpenAI chat 请求 `"max_tokens": 8`，超时 10s） | 请求成功，路由到 `a0`——旧引擎继续正常服务 |

## 预期结果

- 全部步骤通过；epp 的 stderr 日志无 error 级记录（fail 时 harness 自动 dump）。
- 非法流控配置被编译层隔离，旧引擎版本不变、继续服务。

## 清理

`defer e.Close()`：Kill epp/sim 进程并 Wait，关闭 mock API 与 gRPC 连接，`t.TempDir` 自动清理。
