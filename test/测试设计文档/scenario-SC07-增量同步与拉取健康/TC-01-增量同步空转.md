# TC-01 增量同步空转

| 项 | 内容 |
|---|---|
| 用例编号 / 名称 | TC-01 / 增量同步空转 |
| 所属场景 | SC07 增量同步与拉取健康 |
| 版本 | v0.1 |

## 测试目的

验证 InnerAPI 版本增量同步的"零成本空转"语义（FR-D1）：稳态下 poller 持续携带 version 查询参数轮询，`Data: null` 的轮询回合不触发引擎重建；服务端 version 推进但内容字节不变（哈希相同）时同样不重新编译；整个过程中调度服务不受影响。

## 运行模式

单组件进程组：epp（真实进程）×1 + inference-sim（真实进程）×1 + ai-gateway-api mock + BFE 由测试代码扮演。mock 额外按路径记录请求计数（`RequestCount`）与最近一次 version 查询参数（`LastVersionQuery`）。

## 前置条件

1. harness 已构建 epp 二进制；inference-sim 二进制可用。
2. mock API 已配置 assignment（cluster-a=primary）、picker_config（cluster-a 最小配置，无流控）、cluster_table（1 个 sim 后端 a0）。
3. epp 以 `-poll-interval 200ms` 启动并就绪；`ai_epp_engine_current_version{cluster="cluster-a"}` 非空（已有编译引擎）。
4. 记录稳态前的基线值：引擎版本 v1、config 轮询路径 `/configs/epp_data/picker_config` 的请求计数 countBefore。

## 测试步骤

| # | 操作 | 预期 |
|---|---|---|
| 1 | 无任何变更，sleep 1s（约 5 个轮询周期）后再次读取 config 路径请求计数 | 计数增长（轮询未停） |
| 2 | 读取 mock 记录的最近一次 version 查询参数 | 非空（poller 携带 version 参数轮询） |
| 3 | 抓取 epp `/metrics` | `ai_epp_engine_current_version{cluster="cluster-a"}` 仍为 v1；`ai_epp_engine_reloads_total{cluster="cluster-a",result="success"}` = 1（空转期间无重建） |
| 4 | mock 以 `SetConfigs` 下发与当前内容完全相同的 picker_config（同内容推版本，hash 相同），sleep 1s | 版本推进但字节不变：引擎版本仍为 v1，`ai_epp_engine_reloads_total{cluster="cluster-a",result="success"}` 仍为 1（内容哈希去重，不重新编译） |
| 5 | 发送 ext-proc 请求：metadata `llm-d.ai/inference-pool = "cluster-a"`，path `/v1/chat/completions`，body 为 OpenAI chat 请求（`max_tokens: 8`），读取调度响应 | `x-gateway-destination-endpoint` = a0 后端地址（整个过程中调度正常） |

## 预期结果

- 全部步骤通过；轮询未中断、version 参数持续携带、引擎无意外重建、调度结果正确。
- epp 的 stderr 日志无 error 级记录（fail 时 harness 自动 dump）。

## 清理

`defer e.Close()`：Kill epp/sim 进程并 Wait，关闭 mock API 与 gRPC 连接，`t.TempDir` 自动清理。
