# TC-02 拉取健康指标

| 项 | 内容 |
|---|---|
| 用例编号 / 名称 | TC-02 / 拉取健康指标 |
| 所属场景 | SC07 增量同步与拉取健康 |
| 版本 | v0.1 |

## 测试目的

验证两个 poller（discovery / epp_data）的拉取健康可通过 `/metrics` 观测（FR-O2）：最近同步时间戳存在；mock API 故障时失败计数递增、退避状态置位；恢复后退避清零、同步时间更新。

## 运行模式

单组件进程组：epp（真实进程）×1 + inference-sim（真实进程）×1 + ai-gateway-api mock + BFE 由测试代码扮演。mock 支持 `SetFail(bool)` 令全部 InnerAPI 接口返回 500。

## 前置条件

1. harness 已构建 epp 二进制；inference-sim 二进制可用。
2. mock API 已配置 assignment 全量视图（cluster-a → 本实例 primary）、epp_config（cluster-a 最小配置，无流控）、cluster_table（1 个 sim 后端 a0）。
3. epp 以 `-poll-interval 200ms` 启动并就绪，两个 poller 均已完成至少一轮成功同步。

## 测试步骤

| # | 操作 | 预期 |
|---|---|---|
| 1 | 抓取 epp `/metrics`，检查两个 poller 的最近同步时间戳 | `ai_epp_poller_last_sync_timestamp{poller="discovery"}`、`{poller="epp_data"}` 均非 0 |
| 2 | mock `SetFail(true)`（全部接口 500），等待 15s 内轮询失败 | `ai_epp_poller_failures_total{poller="epp_data"}` > 0，且 `ai_epp_poller_backoff_state{poller="epp_data"}` = 1（失败计数递增、进入退避） |
| 3 | 继续观察 discovery poller | 15s 内 `ai_epp_poller_backoff_state{poller="discovery"}` = 1 |
| 4 | mock `SetFail(false)` 恢复 | 15s 内 `ai_epp_poller_backoff_state{poller="epp_data"}` 归零，且 `ai_epp_poller_last_sync_timestamp{poller="epp_data"}` 非 0（退避清除、同步恢复） |

## 预期结果

- 全部步骤通过；API 故障期间仅表现为失败计数与退避状态变化，进程不退出。
- epp 的 stderr 日志无 error 级记录（fail 时 harness 自动 dump）。

## 清理

`defer e.Close()`：Kill epp/sim 进程并 Wait，关闭 mock API 与 gRPC 连接，`t.TempDir` 自动清理。
