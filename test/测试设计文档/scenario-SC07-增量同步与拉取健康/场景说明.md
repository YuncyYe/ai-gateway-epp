# 场景说明：SC07 增量同步与拉取健康

所属场景编号：SC07；代码目录：`test/implementation/scenario-SC07-incremental-sync`（包名 `sc07`）。

## 1. 背景与目的

验证 InnerAPI 版本增量同步的"零成本空转"语义与拉取组件的可观测性（需求分析 FR-D1、FR-O2）：

- 配置无变化时（`Data: null`）轮询继续、但不触发任何引擎重建；
- 服务端 version 推进而**内容字节不变**时，本地按内容哈希去重，同样不重建；
- poller 健康可通过 `/metrics` 观测：最近同步时间、失败计数、退避状态，三个 poller（discovery/config/assignment）各一份。

## 2. 运行模式

同 SC01（单组件进程组，每 TC 独立一套）。mock 增加按路径的请求计数与最近 version 查询参数记录（`RequestCount` / `LastVersionQuery`）。

## 3. TC 列表

| 编号 | 名称 | 断言要点 |
|---|---|---|
| TC-01 | 增量同步空转 | 稳态 1s（约 5 个轮询周期）：config 请求数增长（轮询未停）、携带 version 参数；引擎哈希与 reloads 计数不变；SetConfigs 同内容推版本后依旧不重建；调度正常 |
| TC-02 | 拉取健康指标 | 三个 poller 的 `ai_epp_poller_last_sync_timestamp` 非 0；SetFail(true) 后 `failures_total{poller=config}` 递增且 `backoff_state=1`；恢复后 backoff 清零、sync 时间更新 |

## 4. 观测指标

| 指标 | 标签 | 说明 |
|---|---|---|
| `ai_epp_poller_last_sync_timestamp` | poller | 最近成功同步 Unix 时间 |
| `ai_epp_poller_failures_total` | poller | 失败轮次计数 |
| `ai_epp_poller_backoff_state` | poller | 退避中为 1 |
| `ai_epp_engine_reloads_total` | cluster,result | 引擎重建计数（本场景断言其不变） |
