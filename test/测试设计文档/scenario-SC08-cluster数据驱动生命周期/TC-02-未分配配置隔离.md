# TC-02 未分配配置隔离

| 项 | 内容 |
|---|---|
| 用例编号 / 名称 | TC-02 / 未分配配置隔离 |
| 所属场景 | SC08 cluster 数据驱动生命周期 |
| 版本 | v0.1 |

## 测试目的

验证 epp_config 中出现本实例未分配的 cluster 配置（assignment 中不存在该 cluster）时，epp 不为其建 cell、不编译引擎、零上报，且不影响已分配 cluster 的正常服务（FR-C2 配置隔离）。

## 运行模式

单组件进程组：epp（真实进程）×1 + inference-sim（真实进程）×1 + ai-gateway-api mock + BFE 由测试代码扮演。每 TC 独立一套进程组。

## 前置条件

1. harness 已构建 epp 二进制；inference-sim 二进制可用。
2. mock API 已配置 assignment 全量视图（cluster-a → 本实例 primary）、epp_config（cluster-a 最小配置，cluster-table-discovery 插件钉住 clusterName=cluster-a）、cluster_table（cluster-a 下 1 个 sim 后端 a0，Weight=50）。
3. epp 启动并就绪（health=SERVING，cluster-a cell ready）。

## 测试步骤

| # | 操作 | 预期 |
|---|---|---|
| 1 | mock API 在 epp_config 中额外下发一条 `cluster-ghost` 最小配置，但 assignment 中**不**分配 cluster-ghost | 下发成功 |
| 2 | 等待 1s（覆盖多个轮询周期）后拉取 epp `/metrics`，用 `ai_epp_engine_current_version{cluster=...,version=...}` 检查 cluster-ghost 的引擎版本 | metrics 中无 cluster-ghost 的引擎版本（未编译引擎），即不建 cell |
| 3 | 读取 mock 的 report 计数器 `ReportCount()` | 恒为 0（就绪上报已删除） |
| 4 | 对 epp ext-proc 以 `llm-d.ai/inference-pool = "cluster-a"` 发送 RequestHeaders（path `/v1/chat/completions`）+ RequestBody（OpenAI chat 请求，`"max_tokens": 8`），读取调度返回的 `x-gateway-destination-endpoint` | pick 返回 sim 后端 a0 的 `ip:port`，无错误——未分配配置未扰动已分配 cluster 的服务 |

## 预期结果

- 全部步骤通过；epp 的 stderr 日志无 error 级记录（fail 时 harness 自动 dump）。
- 未分配 cluster 的 epp_config 被完全隔离：无引擎、零上报、无服务影响。

## 清理

`defer e.Close()`：Kill epp/sim 进程并 Wait，关闭 mock API 与 gRPC 连接，`t.TempDir` 自动清理。
