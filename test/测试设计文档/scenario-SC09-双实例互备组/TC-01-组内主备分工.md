# TC-01 组内主备分工

| 项 | 内容 |
|---|---|
| 用例编号 / 名称 | TC-01 / 组内主备分工 |
| 所属场景 | SC09 双实例互备组 |
| 版本 | v0.1 |

## 测试目的

验证里程碑 M3"固定 2 实例互备组"部署模型下的组内分工（FR-H1）：cluster 分配到组后组内再分主备——每个实例只为自己的主 cluster 服务，对备 cluster 的调度请求被拒绝（热数据冷准入）。

## 运行模式

双 epp 实例进程组：`epp-A` / `epp-B`（真实进程，同一 mock API、各自 `-instance-id`）+ inference-sim（真实进程）×2（cluster-a、cluster-b 各一个）+ ai-gateway-api mock（`epp_data/config` 单端点：epp_config + assignment **全量视图**，两实例同一份）+ BFE 由测试代码扮演（分别对 A/B 发起 ext-proc 请求）。

## 前置条件

1. harness 已构建 epp 二进制；inference-sim 二进制可用。
2. mock API 已配置：epp_config（cluster-a、cluster-b 各一份最小配置）、cluster_table（每 cluster 1 个 sim 后端 `cluster-x-0`，Weight=50）。
3. mock API 已通过 `SetAssignmentView` 安装全量视图：`cluster-a = {primary: epp-A, standby: epp-B}`、`cluster-b = {primary: epp-B, standby: epp-A}`（两实例各自以 `-instance-id` 自匹配角色）。
4. epp-A、epp-B 各自启动并就绪（`WaitHealth("", 30s)` 成功，代表 assignment 首拉成功且 cell ready）。

## 测试步骤

| # | 操作 | 预期 |
|---|---|---|
| 1 | 对 epp-A 发 ext-proc 调度请求：RequestHeaders dynamic metadata 带 `llm-d.ai/inference-pool = "cluster-a"`，path `/v1/chat/completions`，随后发送 RequestBody（OpenAI chat 请求，`"max_tokens": 8`，模型 `sim-model`） | 返回 endpoint 为 cluster-a 的 sim 地址（`ip:port`，超时 10s） |
| 2 | 对 epp-A 再发同样的调度请求，pool 换为 `cluster-b` | 请求失败，错误信息含 `not serving`（cell-not-serving，Unavailable），超时 5s |
| 3 | 对 epp-B 发调度请求，pool 为 `cluster-b` | 返回 endpoint 为 cluster-b 的 sim 地址（超时 10s） |
| 4 | 对 epp-B 再发同样的调度请求，pool 换为 `cluster-a` | 请求失败，错误信息含 `not serving`（Unavailable） |
| 5 | 读取 mock 的 report 计数器 `ReportCount()` | 恒为 0（EPP 零上报，failover 由 BFE 滞回驱动） |

## 预期结果

- 全部步骤通过：A 只服务 cluster-a、B 只服务 cluster-b，互为备的 cluster 调度请求均被拒绝且进程存活；
- 全程零上报（退役 report 端点计数器为 0）。
- epp-A、epp-B 的 stderr 日志无 error 级记录。

## 清理

`defer p.Close(t)`：依次 Kill epp-A/epp-B 进程并 Wait，停止各 sim 进程，关闭 mock API；`t.TempDir` 自动清理日志目录。
