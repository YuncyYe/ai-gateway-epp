# TC-02 双活跃容忍

| 项 | 内容 |
|---|---|
| 用例编号 / 名称 | TC-02 / 双活跃容忍 |
| 所属场景 | SC09 双实例互备组 |
| 版本 | v0.1 |

## 测试目的

验证 ai-gateway-api 异常将同一 cluster 同时分配给组内两实例为主时的接受语义（FR-H4）：两实例都正常服务该 cluster（脑裂按容忍处理），且各自在上报中携带 `role=primary` 活跃态——这是双活跃告警的数据源（FR-O4）。

## 运行模式

双 epp 实例进程组：`epp-A` / `epp-B`（真实进程，同一 mock API、各自 `-instance-id`）+ inference-sim（真实进程）×1（cluster-a）+ ai-gateway-api mock（assignment 按 `?instance=` 返回按实例的视图）+ BFE 由测试代码扮演。

## 前置条件

1. harness 已构建 epp 二进制；inference-sim 二进制可用。
2. mock API 已配置：picker_config（cluster-a 最小配置）、cluster_table（cluster-a 1 个 sim 后端 `cluster-a-0`，Weight=50）。
3. mock API 已按实例下发 assignment：`epp-A` 与 `epp-B` 均为 `{cluster-a: primary}`。
4. epp-A、epp-B 各自启动并就绪（`WaitHealth("", 30s)` 成功）。

## 测试步骤

| # | 操作 | 预期 |
|---|---|---|
| 1 | 对 epp-A 发 ext-proc 调度请求：RequestHeaders dynamic metadata 带 `llm-d.ai/inference-pool = "cluster-a"`，path `/v1/chat/completions`，随后发送 RequestBody（OpenAI chat 请求，`"max_tokens": 8`，模型 `sim-model`） | 返回 endpoint 为 cluster-a 的 sim 地址（超时 10s） |
| 2 | 对 epp-B 发同样的调度请求 | 同样返回 cluster-a 的 sim 地址——双主下两实例均可调度（超时 10s） |
| 3 | 在 20s 观察窗口内（`WaitFor`）轮询 mock API 收到的 report 上报，解析每条上报 JSON 中的 `instance` 与 `cells`（`key`/`role`） | 存在 `epp-A` 与 `epp-B` 两条上报，均含 `cluster-a` 且 `role=primary`（assignment 按实例下发经 200ms 轮询生效） |

## 预期结果

- 全部步骤通过：双主分配下两实例都正常服务 cluster-a，无任一侧拒绝。
- 两实例的上报均含 cluster-a 的 `primary` 活跃态，双活跃告警具备数据源。
- epp-A、epp-B 的 stderr 日志无 error 级记录。

## 清理

`defer p.Close(t)`：依次 Kill epp-A/epp-B 进程并 Wait，停止 sim 进程，关闭 mock API；`t.TempDir` 自动清理日志目录。
