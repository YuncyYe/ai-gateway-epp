# 场景说明：SC09 双实例互备组

所属场景编号：SC09；代码目录：`test/implementation/scenario-SC09-dual-instance-group`（包名 `sc09`）。

## 1. 背景与目的

验证里程碑 M3 的"固定 2 实例互备组"部署模型（需求分析 G5、FR-H1、FR-H4）：

- **组内分工**：cluster 分配到组后组内再分主备——A 是部分 cluster 的主、B 是它们的备，反之亦然；每个实例只为自己的主 cluster 服务，对备 cluster 拒绝服务（热数据冷准入）；
- **双活跃容忍**：ai-gateway-api 异常导致同一 cluster 在两实例都被分配为主时，两实例都正常服务（脑裂按接受语义处理），且各自上报 primary 活跃态——这是双活跃告警的数据源（FR-O4）。

## 2. 运行模式

**双 epp 实例进程组**（首次引入多实例）：

| 进程/组件 | 形态 | 说明 |
|---|---|---|
| ai-gateway-epp ×2 | 真实进程 | `epp-A` / `epp-B`，同一 mock API，各自 `-instance-id` |
| inference-sim ×N | 真实进程 | 每 cluster 一个 |
| ai-gateway-api | mock（测试进程内） | assignment 按 `?instance=` 返回**按实例**的视图（`SetAssignments`） |
| BFE | 测试代码扮演 | 分别对 A/B 发起 ext-proc 请求 |

## 3. TC 列表

| 编号 | 名称 | 断言要点 |
|---|---|---|
| TC-01 | 组内主备分工 | A 主 a 备 b、B 主 b 备 a：A 只服务 a、B 只服务 b；对端备请求返回 `not serving`（Unavailable） |
| TC-02 | 双活跃容忍 | cluster-a 同时分配 A/B 为主：两实例都可调度；两实例的上报均含 cluster-a `role=primary` |

## 4. 依赖与就绪

两实例各自 `WaitHealth("", 30s)`；assignment 按实例下发经 200ms 轮询生效，观察窗口 20s。
