# 场景说明：SC09 双实例互备组

所属场景编号：SC09；代码目录：`test/implementation/scenario-SC09-dual-instance-group`（包名 `sc09`）。

## 1. 背景与目的

验证里程碑 M3 的"固定 2 实例互备组"部署模型（需求分析 G5、FR-H1）：

- **组内分工**：assignment 为全量视图（cluster → {primary, standby}，所有实例同一份）；A 是部分 cluster 的主、B 是它们的备，反之亦然；每个实例以 `-instance-id` 自匹配角色，只为自己的主 cluster 服务，对备 cluster 拒绝服务（热数据冷准入）；
- **互备切换 FailoverFlip**：全量视图角色翻转后，新主热接管服务、原主降备拒绝服务。双主（dual-active）在"每 cluster 单 primary"的全量视图下不可表达（api 侧按构造无法错配）；failover 由 BFE 侧 EPPAddr 连接滞回驱动，EPP 零上报，SC03/SC09 仅以 mock report 计数器断言零上报。

实例 id 部署约定：StatefulSet 部署、同参数启动，实例 id = pod hostname（`-instance-id` 缺省值），`/epp-pool` 登记同名；非 K8s 部署显式传 `-instance-id`。若实例 id 未命中任何角色，EPP 无 cell、不服务，并输出告警日志 + 指标 `ai_epp_assignment_no_match`。

## 2. 运行模式

**双 epp 实例进程组**（首次引入多实例）：

| 进程/组件 | 形态 | 说明 |
|---|---|---|
| ai-gateway-epp ×2 | 真实进程 | `epp-A` / `epp-B`，同一 mock API，各自 `-instance-id` |
| inference-sim ×N | 真实进程 | 每 cluster 一个 |
| ai-gateway-api | mock（测试进程内） | `epp_data/config` 两段单端点：epp_config + assignment **全量视图**（所有实例相同，`SetAssignmentView` 直装 / `SetAssignment` 按默认实例展开） |
| BFE | 测试代码扮演 | 分别对 A/B 发起 ext-proc 请求 |

## 3. TC 列表

| 编号 | 名称 | 断言要点 |
|---|---|---|
| TC-01 | 组内主备分工 | 全量视图 A 主 a 备 b、B 主 b 备 a：A 只服务 a、B 只服务 b；对端备请求返回 `not serving`（Unavailable）；零上报 |
| TC-02 | 互备切换 FailoverFlip | 全量视图角色翻转（A 主 B 备 → B 主 A 备）：B 热接管服务、A 降备拒绝服务；零上报 |

## 4. 依赖与就绪

两实例各自 `WaitHealth("", 30s)`；全量视图经 epp_data 轮询（200ms）对两实例同时生效，观察窗口 20s。
