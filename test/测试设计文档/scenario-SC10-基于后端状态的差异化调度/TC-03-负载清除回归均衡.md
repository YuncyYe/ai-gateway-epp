# TC-03 负载清除回归均衡

| 项 | 内容 |
|---|---|
| 用例编号 / 名称 | TC-03 / 负载清除回归均衡 |
| 所属场景 | SC10 基于 vLLM 状态的差异化调度 |
| 版本 | v0.1 |

## 测试目的

验证调度差异化随负载变化可逆：b0 的 fake metrics 从 kv-cache-usage=0.95 清零后，scorer 打分恢复同分，调度回归两后端均被命中的均衡状态（FR-D2）。

## 运行模式

单组件进程组：epp（真实进程）×1 + inference-sim（真实进程，cluster-a 下 a0/b0 两个后端，均启用 fake-metrics）×2 + ai-gateway-api mock + BFE 由测试代码扮演。对应实现 `sc10_test.go` 的 `TestTC03_LoadClearsBackToBalanced`。

## 前置条件

1. 公共前置条件见总体说明 §1-§2。
2. mock API 已配置 assignment（cluster-a=primary）、cluster_table（2 个 sim 后端 a0/b0）；picker_config 由 `WithPickerConfigFn` 下发单 scorer 配置：插件链 cluster-table-discovery + `kv-cache-utilization-scorer`（名称 "kv-scorer"）+ max-score-picker，调度 profile "default" 引用 scorer 与 max-score，requestHandler 为 openai-parser。
3. b0 通过 env 选项 `WithSimFakeMetrics` 启用 fake-metrics（初始 `{}`）；epp 启动并就绪。
4. 指标链路为异步采集（默认 50ms refresh），观察窗口 30s。

## 测试步骤

| # | 操作 | 预期 |
|---|---|---|
| 1 | 对 b0 执行 `POST /admin/config`，body `{"fake-metrics": {"kv-cache-usage": 0.95}}` | 返回 200 |
| 2 | 在 30s 观察窗内连续发送 pick 请求，每轮突发 8 次 | 8 次 pick 全部命中空闲端点 a0，建立"高负载后端被饿死"的初始态 |
| 3 | 对 b0 执行 `POST /admin/config`，body `{"fake-metrics": {"kv-cache-usage": 0}}`，将负载清零 | 返回 200 |
| 4 | 在 30s 观察窗内反复发送 pick 请求（metadata `llm-d.ai/inference-pool = "cluster-a"`，path `/v1/chat/completions`，body 为 OpenAI chat 请求 `"max_tokens": 8`），每轮 5 次、最多 4 轮，收集命中端点 | 两后端打分恢复一致：a0、b0 均被命中，调度回归均衡 |

## 预期结果

- 全部步骤通过；负载清除前 b0 命中数为 0，清除后 a0、b0 均收到流量。
- epp 的 stderr 日志无 error 级记录（fail 时 harness 自动 dump）。

## 清理

`defer e.Close(t)`：Kill epp/sim 进程并 Wait，关闭 mock API 与 gRPC 连接，`t.TempDir` 自动清理。
