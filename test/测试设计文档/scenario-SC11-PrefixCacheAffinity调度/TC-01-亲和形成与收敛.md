# TC-01 亲和形成与收敛

| 项 | 内容 |
|---|---|
| 用例编号 / 名称 | TC-01 / 亲和形成与收敛 |
| 所属场景 | SC11 PrefixCacheAffinity 调度 |
| 版本 | v0.1 |

## 测试目的

验证 prefix-cache-scorer 端到端生效：相同长 prompt 的重复请求在首次随机调度后，其前缀哈希被 approx-prefix-cache producer 自主学习记录到被选后端，后续请求经前缀匹配打分被稳定调度到同一后端（burst=8 全程一致）。

## 运行模式

单组件进程组：epp（真实进程）×1 + inference-sim（真实进程）×2 + ai-gateway-api mock + BFE 由测试代码扮演。

## 前置条件

1. harness 已构建 epp 二进制；inference-sim 二进制可用。
2. mock API 已配置 assignment（cluster-a=primary）、cluster_table（cluster-a 下 2 个 sim 后端 `a0`、`b0`）、picker_config：插件 `ep-discover`（cluster-table-discovery，clusterName=cluster-a）+ `prefix-scorer`（prefix-cache-scorer）+ `max-score`（max-score-picker），scheduling profile default = prefix-scorer → max-score；requestHandler 为 openai-parser。approx-prefix-cache 为注册的默认 data producer，无需显式配置。
3. epp 启动并就绪（health=SERVING）。
4. 请求体为 OpenAI chat completion：`{"model":"sim-model","messages":[{"role":"user","content":"<长 prompt>"}],"max_tokens":8}`；长 prompt 为三个 pangram 重复组合（`"The quick brown fox jumps over the lazy dog. Pack my box with five dozen liquor jugs. How vexingly quick daft zebras jump. "`），跨多个 hash block，保证 matchLen 足以拉开分差。

## 测试步骤

| # | 操作 | 预期 |
|---|---|---|
| 1 | 以 5s 超时调用 `PickEndpoint`：建立 ext-proc gRPC stream，dynamic metadata `llm-d.ai/inference-pool="cluster-a"`，path `/v1/chat/completions`，body 为上述固定长 prompt | 返回一个目标 endpoint（首次无前缀索引，由 max-score-picker 随机选定），无错误 |
| 2 | 对同一 body 连续再 pick 7 次 | 8 次 pick 结果全部一致；不一致则整体重试（sleep 100ms，观察窗口 30s） |
| 3 | 30s 观察窗口内重复步骤 1-2 直到某一轮 8 次 pick 全部命中同一 endpoint | 收敛成功；纯随机 8 连中的概率约 0.8%，可忽略 |
| 4 | 校验收敛端点属于 cluster-a 的 sim 后端集合（`a0`、`b0`） | 收敛端点在 sim 集合内 |

> 索引更新是异步的（`wg.Go`），轮询重试天然覆盖写入时延。

## 预期结果

- 相同长 prompt 的 pick 在 30s 内收敛到单一后端，且该后端为 cluster-a 的合法 sim 端点。
- epp 的 stderr 日志无 error 级记录（fail 时 harness 自动 dump）。

## 清理

`defer e.Close()`：Kill epp/sim 进程并 Wait，关闭 mock API 与 gRPC 连接，`t.TempDir` 自动清理。
