# TC-02 不同前缀独立收敛

| 项 | 内容 |
|---|---|
| 用例编号 / 名称 | TC-02 / 不同前缀独立收敛 |
| 所属场景 | SC11 PrefixCacheAffinity 调度 |
| 版本 | v0.1 |

## 测试目的

验证亲和关系按前缀内容键控：两个内容不同的长 prompt 各自独立收敛到单一后端，互不影响（前缀索引以 prompt 前缀哈希为键，不同前缀学习出各自的亲和目标）。

## 运行模式

单组件进程组：epp（真实进程）×1 + inference-sim（真实进程）×2 + ai-gateway-api mock + BFE 由测试代码扮演。

## 前置条件

同 TC-01：epp_config 为 `ep-discover` + `prefix-scorer`（prefix-cache-scorer）+ `max-score`（max-score-picker），openai-parser；cluster-a 下 2 个 sim 后端 `a0`、`b0`；epp 就绪。

两个不同的长 prompt（均跨多个 hash block）：
- prompt A：`"The quick brown fox jumps over the lazy dog. Pack my box with five dozen liquor jugs. How vexingly quick daft zebras jump. "`
- prompt B：`"Sphinx of black quartz, judge my vow. Waltz, bad nymph, for quick jigs vex. Glib jocks quiz nymph to vex dwarf. "`

## 测试步骤

| # | 操作 | 预期 |
|---|---|---|
| 1 | 构造两个请求体（同一 chat 模板，`max_tokens:8`，仅 content 分别为 prompt A / prompt B），断言二者序列化后不相等 | 两个 body 不同，用例前提成立 |
| 2 | 对 prompt A 的 body 执行收敛轮询：每轮首 pick 定锚，同一轮内连续 6 次 pick 全部一致才算收敛；不一致 sleep 100ms 重试，观察窗口 30s | prompt A 在 30s 内收敛到单一后端 |
| 3 | 对 prompt B 的 body 执行同样的 burst=6 收敛轮询 | prompt B 独立收敛到单一后端 |

## 预期结果

- 两个不同 prompt 各自在 30s 内收敛；亲和按前缀内容键控，互不构成干扰。
- epp 的 stderr 日志无 error 级记录。

## 清理

`defer e.Close()`：Kill epp/sim 进程并 Wait，关闭 mock API 与 gRPC 连接，`t.TempDir` 自动清理。
