# TC-03 热加载后亲和重学

| 项 | 内容 |
|---|---|
| 用例编号 / 名称 | TC-03 / 热加载后亲和重学 |
| 所属场景 | SC11 PrefixCacheAffinity 调度 |
| 版本 | v0.1 |

## 测试目的

验证配置热加载换引擎后内存前缀索引随旧引擎销毁重置、亲和自动重新学习：同一 prompt 在新引擎上重新收敛，服务不中断（FR-C3 引擎切换语义）。

## 运行模式

单组件进程组：epp（真实进程）×1 + inference-sim（真实进程）×2 + ai-gateway-api mock + BFE 由测试代码扮演。

## 前置条件

同 TC-01：picker_config 为 `ep-discover` + `prefix-scorer`（prefix-cache-scorer）+ `max-score`（max-score-picker），openai-parser；cluster-a 下 2 个 sim 后端 `a0`、`b0`；epp 就绪；请求体使用 TC-01 的固定长 prompt（`max_tokens:8`）。

## 测试步骤

| # | 操作 | 预期 |
|---|---|---|
| 1 | 对固定长 prompt 的 body 执行收敛轮询（每轮首 pick 定锚，连续 6 次 pick 一致，观察窗口 30s） | 热加载前亲和收敛到单一后端 |
| 2 | 拉取 epp `/metrics`，解析 `ai_epp_engine_current_version{cluster="cluster-a"}` 记录版本 v1 | v1 非空 |
| 3 | 通过 mock API 重新下发 cluster-a 的 picker_config，仅将插件名 `prefix-scorer` 改名为 `prefix-scorer-v2`（配置仍合法） | 配置提交成功 |
| 4 | 轮询 `/metrics` 中的 `ai_epp_engine_current_version{cluster="cluster-a"}`（WaitFor，20s 窗口，100ms 间隔） | 版本变为非空且不等于 v1：引擎完成热交换，进程无重启，前缀索引随旧引擎销毁重建为空 |
| 5 | 对同一 body 再次执行收敛轮询（burst=8，观察窗口 30s） | 新引擎上亲和自动重新学习并收敛到单一后端 |

## 预期结果

- 热加载前后两个版本均出现且不同，换引擎过程服务不中断。
- 索引重置后同一 prompt 无需人工干预即可重新收敛。
- epp 的 stderr 日志无 error 级记录。

## 清理

`defer e.Close()`：Kill epp/sim 进程并 Wait，关闭 mock API 与 gRPC 连接，`t.TempDir` 自动清理。
