# TC-03 绑定端点摘除迁移

| 项 | 内容 |
|---|---|
| 用例编号 / 名称 | TC-03 / 绑定端点摘除迁移 |
| 所属场景 | SC12 SessionAffinity 调度 |
| 版本 | v0.1 |

## 测试目的

验证绑定端点被摘除（Weight=0 退出候选集）时，session 自动迁移到存活端点并重新粘住。

## 运行模式

单组件进程组：epp（真实进程）×1 + inference-sim（真实进程）×2 + ai-gateway-api mock + BFE 由测试代码扮演。harness、mock 与二进制构建见总体说明 §1-§2。

## 前置条件

同 TC-01：epp_config 为 cluster-table-discovery + session-affinity-scorer（session_id，header `x-session-id`）+ max-score-picker；cluster-a 挂 2 个 sim 后端 a0/b1；epp 启动并就绪。

## 测试步骤

| # | 操作 | 预期 |
|---|---|---|
| 1 | `stick(sess-migrate, 6)`：带 header `x-session-id: sess-migrate` 连续 6 次 pick 收敛 | session 粘住某一端点（首次落点随机） |
| 2 | 通过 mock API 的 cluster_table 下发摘除：若绑定在 a0 则 a0 Weight=0、b1 Weight=50；若绑定在 b1 则 b1 Weight=0、a0 Weight=50 | 绑定端点退出候选集，另一存活端点 Weight=50 |
| 3 | 30s 观察窗口内轮询带 `x-session-id: sess-migrate` 的 pick，直至命中存活端点 | session 迁移到存活端点 |
| 4 | `stick(sess-migrate, 8)`：迁移后再连续 8 次 pick | 8 次全部命中存活端点，重新粘住 |

## 预期结果

- 全部步骤通过；绑定端点摘除后 session 在 30s 内迁移到存活端点并重新粘住。
- epp 日志无 error 级记录。

## 清理

`defer e.Close(t)`：Kill epp/sim 进程并 Wait，关闭 mock API 与 gRPC 连接，`t.TempDir` 自动清理。
