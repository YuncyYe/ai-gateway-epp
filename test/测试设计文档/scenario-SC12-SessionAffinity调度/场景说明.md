# 场景说明：SC12 SessionAffinity 调度

所属场景编号：SC12；代码目录：`test/implementation/scenario-SC12-session-affinity`（包名 `sc12`）。

## 1. 背景与目的

验证 **session-affinity-scorer**（`session_id` 策略）端到端生效：从请求 header 解析 session id → 调度后绑定 session→端点 → 同 session 请求稳定粘住；绑定端点被摘除（Weight=0 退出候选集）时自动迁移并重新粘住。

机制出处：`llm-d-router/pkg/epp/framework/plugins/scheduling/scorer/sessionaffinity/`（scorer 与 filter 两个形态）、`.../scheduling/util/sessionaffinity/session_id.go`（绑定/迁移/TTL 逐出逻辑）。

## 2. 前置产品改动（本场景引入）

- `cmd/epp/plugins.go` 注册 `session-affinity-scorer`（此前 ai-gateway-epp 未开放该插件）。filter 形态（`session-affinity-filter`）与 `session-id-producer`（把 session id 发布为 endpoint attribute 的另一条链路）暂未注册。
- `test/common/extproc_client.go` 新增 `PickEndpointWithHeaders`，支持在 RequestHeaders 携带任意 header（本场景注入 `x-session-id`）。

## 3. 配置构造

```
plugins: cluster-table-discovery + session-affinity-scorer + max-score-picker
scorer 参数: strategy=session_id, sessionIdConfig.sources=[{header: "x-session-id"}]
```

行为语义：无 session header → scorer 弃权（全 0 分），picker 自由选（无错误）；已绑定 → 目标 1.0 其余 0.0；绑定端点不在候选集 → 迁移并重新绑定（TTL 300s 逐出，本场景不涉及）。

## 4. TC 列表

| 编号 | 名称 | 断言要点 |
|---|---|---|
| TC-01 | session 粘住 | 带 `x-session-id` 的请求连续 8 次命中同一端点；无端 header 请求不受影响（弃权正常调度） |
| TC-02 | 多 session 独立 | 两个 session 各自粘住、交错请求绑定互不干扰 |
| TC-03 | 绑定端点摘除后迁移 | 摘除 session 绑定的端点（Weight=0）→ session 迁移到存活端点并重新粘住 |

## 5. 断言方式

`stick` 辅助：每轮以首次 pick 为锚点要求整 burst 一致，轮询至收敛（绑定写入是调度路径同步完成，但首次调度本身是随机选择，需给绑定落定留重试窗口）。观察窗口 30s。

同 SC01 §5。
