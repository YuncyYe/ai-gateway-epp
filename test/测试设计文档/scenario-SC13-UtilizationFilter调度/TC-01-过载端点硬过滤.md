# TC-01 过载端点硬过滤

| 项 | 内容 |
|---|---|
| 用例编号 / 名称 | TC-01 / 过载端点硬过滤 |
| 所属场景 | SC13 UtilizationFilter 调度 |
| 版本 | v0.1 |

## 测试目的

验证 utilization-filter 的硬过滤语义：`kv-cache-utilization` 超过阈值（maxValue=0.9）的端点被**移出候选集**（区别于 SC10 scorer 的软偏好——低分仍可能被选中）；负载清零后端点重新成为候选，调度自动回归。

## 运行模式

单组件进程组：epp（真实进程）×1 + inference-sim（真实进程）×2 + ai-gateway-api mock + BFE 由测试代码扮演。实例 ID `epp-sc13-tc01`，cluster-a 下辖 a0、b0 两个 sim 后端。

## 前置条件

1. harness 已构建 epp 二进制；inference-sim 二进制可用（`INFERENCE_SIM_BIN` 或 sibling checkout，缺失则 skip）。
2. mock API 已配置 assignment 全量视图（cluster-a → 本实例 primary）、cluster_table（cluster-a = a0、b0）、epp_config（utilFilterConfig：ep-discover + util-filter + max-score-picker，**无 scorer**）。
3. util-filter 参数：`conditions=[{"metric":"kv-cache-utilization","maxValue":0.9}]`，`fallbackOnEmpty=false`。
4. 两个 sim 启动时均启用 fake-metrics（`WithSimFakeMetrics` 初始值 `{}`），用于运行时下发受控的 kv-cache 利用率。

## 测试步骤

| # | 操作 | 预期 |
|---|---|---|
| 1 | 基线阶段：以 gRPC 客户端连 epp ext-proc 发 PickEndpoint（pool=`cluster-a`，path=`/v1/chat/completions`，body 为 OpenAI chat 请求 `{"model":"sim-model","messages":[...],"max_tokens":8}`），重复轮询直至 5 次内命中两个不同后端 | a0、b0 均被命中（基线双端点均衡） |
| 2 | `SetSimFakeMetrics` 向 b0 下发 `kv-cache-usage=0.95`（>0.9 阈值），随后连续 5 次 PickEndpoint | 5 次全部成功且全部命中 a0（b0 被硬移除，而非仅降低选中概率） |
| 3 | `SetSimFakeMetrics` 将 b0 的 `kv-cache-usage` 清零，重新轮询直至 5 次内再次命中两个后端 | a0、b0 均被命中，过滤解除、调度回归 |

注：fake-metrics 下发后指标采集为异步路径，各阶段观察窗口分别为 20s / 30s / 30s（WaitFor 轮询）。

## 预期结果

- 全部步骤通过；b0 超阈值期间不存在任何一次命中 b0 的 pick。
- epp 进程无 panic，liveness 正常；stderr 无 error 级记录（fail 时 harness 自动 dump）。

## 清理

`defer e.Close(t)`：Kill epp/sim 进程并 Wait，关闭 mock API 与 gRPC 连接，`t.TempDir` 自动清理。
