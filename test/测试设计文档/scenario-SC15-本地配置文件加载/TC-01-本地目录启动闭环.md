# TC-01 本地目录启动闭环

| 项 | 内容 |
|---|---|
| 用例编号 / 名称 | TC-01 / 本地目录启动闭环 |
| 所属场景 | SC15 本地配置文件加载 |
| 版本 | v0.1 |

## 测试目的

验证仅凭 `--local-config-dir` 指向的本地文件，EPP 即可完成全部集群级配置加载：`cluster_table.json` 端点集与 `epp_data_config.json`（引擎 + assignment）均生效，进程就绪、cell 建立、引擎编译、端点可被调度命中；全过程不连接 InnerAPI、不访问推理后端。

## 运行模式

单组件进程组：epp（真实进程）×1；**不启动** mock api / inference-sim。ext-proc 仅用于读取 EPP 选点。对应实现（拟）`sc15_test.go` 的 `TestTC01_LocalConfigStartup`（env 标识 `epp-sc15-tc01`）。

## 前置条件

1. harness 已构建 epp 二进制。
2. 本地配置目录含三份文件：
   - `cluster_table.json`：`cluster-a.sub-1 = [ {Name: "cluster-a-0", Addr: "127.0.0.1", Port: portA, Weight: 50} ]`（portA 为保留端口，无监听）。
   - `epp_data_config.json`：`epp_config["cluster-a"]` = 最小配置；`assignment["cluster-a"] = {primary: 本实例, standby: null}`。
   - `epp_pool.json`：含本实例占位。
3. epp 以 `--local-config-dir=<dir> --instance-id=<本实例> -poll-interval=200ms` 启动。

## 测试步骤

| # | 操作 | 预期 |
|---|---|---|
| 1 | 启动 epp，等待 gRPC 端口可连接 | 进程监听成功 |
| 2 | `WaitHealth("", 30s)` | readiness SERVING；`Check("liveness")` SERVING |
| 3 | 抓取 `/metrics`，断言 `ai_epp_engine_current_version{cluster="cluster-a"}` 存在且 version 非空 | epp_config 已编译换入 |
| 4 | 断言 `ai_epp_engine_reloads_total{cluster="cluster-a",result="success"}` ≥ 1 | 至少一次成功编译 |
| 5 | 断言 `ai_epp_cell_state{cluster="cluster-a",role="primary",state="primary"}` = 1 | assignment 生效、建主 cell |
| 6 | 断言 `ai_epp_assignment_no_match` = 0 | 本实例在 assignment 中匹配到角色 |
| 7 | 断言 `ai_epp_poller_last_sync_timestamp{poller="discovery"}` > 0、`{poller="epp_data"}` > 0 且两者 `backoff_state` = 0、`failures_total` = 0 | 两份文件均解析成功并应用 |
| 8 | ext-proc `PickEndpoint(pool="cluster-a", path="/v1/chat/completions", 超时 10s)` | 返回 `127.0.0.1:portA`（cluster_table 端点被命中，不连接后端） |

## 预期结果

- 步骤 2：readiness 与 liveness 均 SERVING。
- 步骤 3–7：epp_data_config 的引擎/assignment 与 cluster_table 的端点集全部加载生效。
- 步骤 8：调度返回 cluster_table 内端点，证明端点注册链路正确。
- 全程无对 `-api-addr`（默认值）与后端的网络请求。

## 清理

`defer e.Close()`：Kill epp 进程并 Wait，`t.TempDir` 自动清理配置目录与日志。
