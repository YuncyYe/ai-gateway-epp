# TC-05 本地文件轮询自动重载

| 项 | 内容 |
|---|---|
| 用例编号 / 名称 | TC-05 / 本地文件轮询自动重载 |
| 所属场景 | SC15 本地配置文件加载 |
| 版本 | v0.1 |

## 测试目的

验证本地文件模式下无需重启、无需文件监听（inotify）：`LocalFileSource.Fetch` 每轮恒 `changed=true`，poller 每个轮询周期重读文件并应用，因此运行中修改 `epp_data_config.json` / `cluster_table.json` 会在下一个轮询周期自动生效。

> 说明：2026-09-14 设计文档称"修改文件需重启"，与实现行为不符（实现为按 poll 间隔自动重读）。本 TC 按**实现行为**设计，差异见场景说明 §8，待评审确认。

## 运行模式

同 TC-01（epp 真实进程 ×1，无 mock/sim）。对应实现（拟）`TestTC05_PollReload`（env 标识 `epp-sc15-tc05`）。

## 前置条件

- 初始 `cluster_table.json`：`cluster-a.sub-1 = [portA]`；`epp_data_config.json`：cluster-a 最小配置（插件名 `max-score`）。
- epp 就绪，记录 `v1 = ai_epp_engine_current_version{cluster="cluster-a"}`。

## 测试步骤

| # | 操作 | 预期 |
|---|---|---|
| 1 | 重写 `epp_data_config.json`：将插件 `max-score` 重命名为 `max-score-v2`（内容哈希变化、仍合法） | 文件落盘 |
| 2 | `WaitFor(20s)` 轮询 metrics，等待 cluster-a 引擎版本变化 | `ai_epp_engine_current_version` 从 v1 变为非空新值（无需重启） |
| 3 | 重写 `cluster_table.json`：`cluster-a.sub-1 = [portC]`（新保留端口） | 文件落盘 |
| 4 | `WaitFor(20s)` 反复 ext-proc pick `pool="cluster-a"`，直到返回 `127.0.0.1:portC` | 新端点被调度命中，旧端点不再返回 |
| 5 | 断言进程未重启（同一 PID / gRPC 连接持续可用） | 无重启 |

## 预期结果

- 修改两份被消费文件后，引擎与端点集均在 poll 周期内自动更新，进程无重启。
- 观测：`ai_epp_engine_current_version` 哈希前移、ext-proc 选点端口变化。

## 清理

`defer e.Close()`。
