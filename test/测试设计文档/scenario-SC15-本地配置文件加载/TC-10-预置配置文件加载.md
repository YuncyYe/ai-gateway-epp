# TC-10 预置配置文件加载

| 项 | 内容 |
|---|---|
| 用例编号 / 名称 | TC-10 / 预置配置文件加载 |
| 所属场景 | SC15 本地配置文件加载 |
| 版本 | v1.0（2026-10-15 新增） |

## 测试目的

验证 `--local-config-dir` 指向**随仓库跟踪的预置配置目录**（而非测试临时生成）时，EPP 能直接读取磁盘上的三份文件并生效：`epp_data_config.json` 编译出引擎并完成组匹配、`cluster_table.json` 提供端点、`epp_pool.json` 不参与运行时。与 TC-01（临时生成配置）互补——本用例证明"生产/交付形态下的固定配置目录"可被原样加载。

参照配置文件：`ai-gateway-epp/conf/epp_data_conf/`；本用例使用仓库内预置目录
`test/implementation/scenario-SC15-local-config-file/testdata/epp_data_conf/`（内容见该目录 `README.md`）：

- cluster：`cluster-a`；`assignment.group = epp-sc15-tc10`（与本用例 `-epp-group` 对应）；
- `epp_data_config.json` 的 `epp_config["cluster-a"]` 为**完整形态**配置：`featureGates: ["flowControl"]`、
  `cluster-table-discovery`、`utilization-filter` + `utilization-detector`（saturation-detector）、
  `kv-cache-utilization-scorer`、`session-affinity-scorer`、`queue-scorer`、`prefix-cache-scorer`、
  `max-score-picker`、`openai-parser`，以及 `flowControl` 区块（maxRequests/priorityBands/saturationDetector）；
- `cluster_table` 端点：`127.0.0.1:18981`（保留回环端口，本场景不访问后端）；
- `epp_pool.json` 组名 `epp-sc15-tc10`（EPP 不消费）。

## 运行模式

单组件进程组：ai-gateway-api **不启动**（无 mock）；llm-d-inference-sim **不启动**；只拉起 1 个真实 `ai-gateway-epp`（`--local-config-dir <testdata/epp_data_conf>`）；BFE 由测试代码以 ext-proc gRPC 客户端扮演（只读选点，不连后端）。日志目录用 `t.TempDir()`。

## 前置条件

1. harness 可 `go build ./cmd/epp`；
2. 仓库内存在 `test/implementation/scenario-SC15-local-config-file/testdata/epp_data_conf/`（含 `epp_data_config.json` / `cluster_table.json` / `epp_pool.json`），内容与断言一致，**运行期不得改写**；
3. 无需 inference-sim（本场景不访问推理服务）。

## 测试步骤

| # | 操作 | 预期 |
|---|---|---|
| 1 | 以 `--local-config-dir <testdata/epp_data_conf> -epp-group epp-sc15-tc10` 启动 epp | 进程监听 gRPC/health/metrics |
| 2 | `WaitHealth("", 45s)` 等待就绪 | readiness SERVING（epp_data 首拉 + cell Ready） |
| 3 | 抓取 `/metrics`：`ai_epp_engine_current_version{cluster="cluster-a"}`、`ai_epp_cell_state{cluster="cluster-a",state="active"}`、`ai_epp_assignment_no_match`、两 poller（`discovery`/`epp_data`）的 `last_sync_timestamp`/`backoff_state`/`failures_total` | 引擎版本非空、cell_state=1、`assignment_no_match=0`、两 poller 均已同步且无退避/失败 |
| 4 | 计算 `sha256(epp_config["cluster-a"] 的原始 JSON 字节)` 并与 `ai_epp_engine_current_version` 比对 | **两者相等**——引擎就是用该文件内容（含上述完整插件链与 flowControl）编译的，非默认/残留配置 |
| 5 | 读取 `ai_epp_engine_reloads_total{cluster="cluster-a",result="success"}` | ≥ 1（该文件的配置成功编译并换入） |
| 6 | ext-proc `PickEndpoint(pool=cluster-a)`（请求体为 chat，10s 超时） | 返回 `127.0.0.1:18981`，即 `testdata/cluster_table.json` 中声明的端点（**不访问后端**） |

## 预期结果

- 预置目录中的配置被原样加载：引擎编译成功（**引擎版本 == 文件内容的 sha256**，见 `cell.HashConfig`）、assignment 组名匹配、cluster_table 端点被调度命中；
- 全程不连接 ai-gateway-api InnerAPI，也不向后端发起推理请求；
- 预置文件在测试中保持不变（用例只读）。

## 与其它 TC 的关系

- **TC-01**（临时生成配置目录）验证加载链路；**TC-10** 验证"固定/交付形态的配置目录"可原样消费，等价于把 `conf/epp_data_conf` 的三份样例直接用于运行；
- TC-05/TC-06/TC-07 需要构造变体（重载、缺失、损坏），仍使用 `t.TempDir()` 生成，不改写 testdata。

## 清理

停止 epp 进程（`env.Proc.Stop(t)`）。
