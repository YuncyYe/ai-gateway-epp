# 场景说明：SC15 本地配置文件加载

所属场景编号：SC15；代码目录（拟）：`test/implementation/scenario-SC15-local-config-file`（包名 `sc15`）。

## 1. 背景与目的

验证 `--local-config-dir` 本地配置文件加载模式（设计文档：`docs/zh_cn/modifications/2026-09-14-local-config-file/design-changes.md`，以及 `2026-09-20-reload-local-conf/design-changes.md`）：

- 当 `--local-config-dir` 非空（或设置环境变量 `AI_GATEWAY_EPP_LOCAL_CONFIG_DIR`）时，EPP 从本地目录读取集群级配置，**完全不连接 ai-gateway-api InnerAPI**。
- 目录内两份被消费的文件被正确解析并生效：
  - `cluster_table.json` → `ClusterDiscovery` / hub（后端端点集）
  - `epp_data_config.json` → `EppDataWatcher`（`epp_config` 引擎编译 + `assignment` 角色/建 cell）
  - `epp_pool.json` 不参与运行时（设计文档标注"否"，见 §7 说明）
- 本地文件加载失败继承 fail-static：不更新状态、退避重试（`pkg/poller/poller.go`）。

**本场景范围限定**：只验证"配置被正确加载并生效"，**不访问推理服务**。因此不启动 llm-d-inference-sim，cluster_table 中的端点使用本机保留（不监听）的回环端口；仅通过 EPP 自身的可观测信号（metrics / gRPC health / ext-proc 调度决策）判定加载正确，**不向后端发起任何 HTTP 推理请求**。

## 2. 运行模式

单组件进程组（每 TC 独立一套）：ai-gateway-api **不启动**（除 TC-08 为验证零访问而启动 mock 计数器）；llm-d-inference-sim **不启动**；只拉起 1 个真实 ai-gateway-epp 进程；BFE 由测试代码以 ext-proc gRPC 客户端扮演（仅读取 EPP 返回的选点，不连接后端）。

全部监听 `127.0.0.1`，端口 `FindFreePort` 动态分配；`t.TempDir()` 作为本地配置目录与日志目录。

## 3. 配置构造

本地配置目录含三份文件（TC-06/07/09 有缺省/损坏变体），格式见 2026-09-14 设计文档 §4.2：

- `cluster_table.json`：`{ "<cluster>": { "sub-1": [ {Name,Addr,Port,Weight} ] } }`，Addr=`127.0.0.1`、Port 为保留端口，Weight=50。
- `epp_data_config.json`：`{"epp_config": {"<cluster>": <EndpointPickerConfig>}, "assignment": {"<cluster>": {primary, standby}}}`；`epp_config` 与现有 `common.EppConfig()` 等价（ep-discover / kv-scorer / queue-scorer / max-score + schedulingProfiles + dataLayer + requestHandler）。
- `epp_pool.json`：`{name, groups:[{name, instances:[{id,host,port}]}]}`，仅为参考文件（见 §7）。

两个 cluster 的构造（TC-03）：`cluster-a`、`cluster-b` 各自独立 `epp_config`（`cluster-table-discovery.parameters.clusterName` 指向自身）与独立端点。

## 4. 观测手段

| 观测点 | 指标 / 接口 | 含义 |
|---|---|---|
| epp_data 加载成功 | `ai_epp_engine_current_version{cluster,version}` 存在且 version 非空 | `epp_config` 已编译并换入引擎 |
| 引擎编译 | `ai_epp_engine_reloads_total{cluster,result="success"}` ≥ 1 | 至少一次成功编译 |
| assignment 自匹配 | `ai_epp_assignment_no_match` = 0 | 本实例在 assignment 中匹配到角色 |
| cell 生命周期 | `ai_epp_cell_state{cluster,role,state}` | `primary/primary`（主）或 `standby/standby`（热备） |
| cluster_table 加载成功 | `ai_epp_poller_last_sync_timestamp{poller="discovery"}` > 0 且 `backoff_state=0` | 文件解析成功并应用 |
| epp_data 拉取健康 | `ai_epp_poller_last_sync_timestamp{poller="epp_data"}`、`failures_total{poller="epp_data"}`、`backoff_state{poller="epp_data"}` | 失败/退避/恢复 |
| 就绪 | gRPC health `Check("")` = SERVING（liveness 恒 SERVING） | epp_data 首拉 + 全部 cell Ready |
| 端点真实生效 | ext-proc `PickEndpoint` 返回 `x-gateway-destination-endpoint` | cluster_table 端点被调度命中（**不访问后端**） |

## 6. 依赖与就绪

1. 本机可 `go build ./cmd/epp`（harness 自动构建）。
2. **不依赖 inference-sim**：本场景全部 TC 无需 `INFERENCE_SIM_BIN`，因此不会因 sim 缺失而 `t.Skip`。
3. 就绪门控：`WaitForTCP(gRPC)` 确认进程监听；就绪 TC 用 `WaitHealth("", 30s)`；fail-static TC 允许 readiness NOT_SERVING，但要求 liveness SERVING。
4. 轮询间隔 200ms（harness 参数），版本/重载观察窗口 20s；退避恢复观察窗口 45s（退避上限 30s）。

## 7. 新增 harness 设计（拟）

新增 `test/common/local_env.go`（不启动 mock/sim）：

- `LocalEnv{ EPP *EppEnv; ConfigDir string; ClusterSims map[string][]string; API *MockAPI }`，`Close()` 停止 epp 并按需关闭 mock。
- `NewLocalEnv(t, instanceID, clusters, opts...)`：按 cluster→逻辑后端名生成保留端口端点，写三份文件，启动 epp（默认 `--local-config-dir`），等待就绪。
- Options：`WithLocalEppArgs`、`WithLocalConfigEnvVar`（改用环境变量）、`WithLocalRoles`（primary/standby）、`WithLocalObservedAPI`（启 mock 并传 `-api-addr`）、`WithLocalEppConfigFn`。
- 低层原语供 fail-static TC 使用：`StartLocalEPP(t, logDir, configDir, instanceID, apiAddr, extraArgs...)`（等待 gRPC 监听，不等就绪）、`WriteClusterTableFile`、`WriteEppDataConfigFile`、`WriteEppPoolFile`、`EppDataConfigFor`。
- 空白端口：`FindFreePort` 仅用于生成"保留端口"，返回后不监听，作为假端点。

## 8. 与设计文档的差异说明（需评审确认）

1. **轮询自动重载**：2026-09-14 文档 §4.1/§9 称"不加文件监听、修改文件需重启 EPP"；但实现中 `LocalFileSource.Fetch` 恒返回 `changed=true`，poller 每个轮询周期都会重新读文件并应用，因此**运行中修改文件会在下一个轮询周期自动生效（等价于按 poll 间隔热加载，无 inotify）**。TC-05 按实现行为设计；若后续仅保留 HTTP `/reload/local-config` 触发（2026-09-20 文档），TC-05 需相应调整。
2. **`epp_pool.json` 不被消费**：2026-09-14 文档明确注明"否（仅校验/文档用途）"，与当前实现一致，TC-09 据此设计；2026-09-20 文档提出 reload 时校验 instance-id，尚未实现，若落地则 TC-09 需改为"非法 pool 触发 reload 失败"。
3. **退避时延**：fail-static 自愈受指数退避影响（1s→2s→…→30s 封顶），TC-06/07 自愈窗口放宽至 45s。
